# 消息时间与整轮耗时验收

日期：2026-11-12。

## 变更

- 保留消息分页及实时事件外层的 `startedAtMs`、`completedAtMs`，用户消息和 AI 回复显示发送/输出时间，悬停显示完整日期，使用浏览器本地时区。
- 首个有时间的消息、跨本地日期或相邻消息间隔至少 30 分钟时显示时间分隔线。
- 整轮任务运行中每秒刷新已用时，完成、停止或失败后保留结果；追加要求沿用同一轮计时。优先使用执行端 `durationMs`，缺失时根据开始与结束时间计算；不将其解释为纯模型推理耗时。
- 命令卡片显示工具自身的执行时长。消息、轮次时间缺失时不使用本机接收/刷新时间补造。
- 历史正文继续使用原有分页；新增同一鉴权路径下的 `view=timing` 轮次元数据分页，每页 50 轮。优先 `notLoaded`，执行端明确不支持时回退 `summary`，响应仅保留 ID、状态及时间字段，不传递工具正文。首次持久化前的已知“轮次尚不可用”响应返回空列表。
- 时间状态仅保存在当前页面内存中，从 app-server 恢复，不新增本地项目或历史数据库。

## 隔离环境

从根目录及 Web Compose 生成独立项目 `codex-message-time-acceptance`，MQTT 18887、Web 31027，使用独立 home、workspace、Broker 数据和 Web 用户数据。配置在 Git 忽略的 `acceptance/.runtime/message-time`、`web/test-results`，只复用此前验收的依赖与前端构建卷。

Codex 为本机已有镜像中的 0.167.0，桥使用仓库当前源码。浏览器使用镜像预装 Playwright 1.65.0 与 Chromium headless shell，未安装浏览器。两个浏览器上下文分别设置为东京及 UTC 时区。

验收目录、线程及账号使用随机名称并记录。脚本清理自己创建的线程和目录，保留账号与报告。正式桌面、原有项目和用户数据未操作，正式 Web 未重启。
